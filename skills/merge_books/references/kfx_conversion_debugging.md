# KFX Conversion Failure: Multi-Chapter Merged Files

Detailed debugging trace from Into Thin Air (进入空气稀薄地带) session, June 28 2026.

## Symptom

Merged Markdown files containing 2+ chapters (e.g., `merged_ch01_02.md`, 51KB) fail KFX conversion. Calibre's KFX Output plugin invokes Kindle Previewer 3 CLI, which reports:

```
Book Conversion failed.
Kindle conversion has encountered an internal error.
Recommended Fix: Our team needs to investigate this error...
```

The conversion falls back to EPUB (58KB) but no KFX is produced.

## What Was Ruled Out

All of these were tested and did NOT fix the issue:

| Test | Result |
|------|--------|
| Single chapter (ch01.md, 19KB) | KFX SUCCESS (82KB) |
| Single chapter (ch02.md, 36KB) | KFX SUCCESS (301KB) |
| Combined ch1+ch2 (51KB) | KFX FAILED |
| Removed Footnotes section | KFX FAILED |
| Removed TOC entirely (`generate_toc_html = lambda: ''`) | KFX FAILED |
| Removed all `---` horizontal rules | KFX FAILED |
| Fixed anchor ID mismatches (H1 skip in add_anchor_ids) | KFX FAILED |
| Fixed TOC HTML nesting (level normalization) | KFX FAILED |

## What Was Confirmed Working

| File | XHTML Size | KFX | Notes |
|------|-----------|-----|-------|
| Born to Run merged_25-32.md | 556KB | YES (1.1MB KFX) | 8 chapters in one XHTML, works fine |
| Into Thin Air ch01.md solo | ~20KB | YES (82KB KFX) | |
| Into Thin Air ch02.md solo | ~36KB | YES (301KB KFX) | |
| Into Thin Air merged_ch01_02.md | 382KB | NO | Internal error |

## Key Insight

Born to Run (556KB, 8 chapters) converts fine but Into Thin Air (382KB, 2 chapters) does not. The difference is NOT size — it's something in the specific content combination of Into Thin Air's chapters. Born to Run was generated by the same md2kfx pipeline with identical EPUB structure (single content.xhtml, same OPF manifest).

## md2kfx.py Bugs Found and Fixed

### Bug 1: add_anchor_ids() H1 mismatch

`extract_toc()` skips the first H1 (book title), but `add_anchor_ids()` only matched `#{2,6}` patterns, causing all anchors to be off by one. TOC links pointed to non-existent targets.

**Fix**: Changed `add_anchor_ids()` to match `#{1,6}` and skip the first H1 explicitly, matching `extract_toc()` behavior.

### Bug 2: generate_toc_html() invalid nesting

When headings go H1→H2→H3 (after extract_toc skips H1), the level normalization assumed min_level=2. With H1 in the mix, it produced HTML like:
```html
<ul>
</ul>           <!-- empty, invalid -->
<li>...          <!-- outside <ul> -->
<ul>
<ul>             <!-- double-nested, invalid -->
```

**Fix**: Normalize levels so min_level maps to 2 before processing.

These fixes resolved the "Hyperlink not resolved" warnings from Kindle Previewer, but did NOT fix the "internal error" — that's a separate, deeper issue in Kindle Previewer 3's processing of the content.

## Conversion Pipeline Details

```
Markdown → HTML (python-markdown) → EPUB (ebooklib) → KFX (calibre KFX Output plugin → Kindle Previewer 3 CLI)
```

- Kindle Previewer 3 CLI takes ~300 seconds per book
- Calibre KFX Output plugin version: 2.18.0, calibre 9.4
- Kindle Previewer version: 3.102.0
- KPR CLI logs at: `%TEMP%/calibre-*/[hash]/[hash]/0000/log_KPR_CLI.txt`
- Use `ebook-convert ... --show-kpr-logs` to surface KPR logs inline

## MCP Server Behavior

- `mcp_tokindle_upload_local_file()` spawns a daemon thread for conversion
- If `ebook-convert.exe` or `calibre-parallel.exe` are killed externally, the daemon thread dies silently
- All subsequent uploads show `status: "uploaded"` forever — never converts
- Recovery: restart the MCP server (Hermes restart)
- The upload always succeeds (copies MD to uploads/), only conversion fails

## Workaround

Convert individual chapter files (chNN.md) separately via MCP upload, or copy generated EPUBs directly to Kindle's `F:\documents\Downloads\Items01\article\` folder.

## Next Steps for Investigation
